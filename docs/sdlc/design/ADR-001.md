> **Superseded by [ADR-002](ADR-002.md) on 2026-10-29.** The owner chose not to use third-party hosting, so the game runs on their PC instead. Kept for the decision history.

## Context

The game has to be playable from a public URL. It needs WebSockets (Socket.IO), and the design doc limits hosting to free tiers. Releases R1 and R2 keep rooms in server memory.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| Render free web service | WebSockets supported; deploys from `render.yaml`; health checks | Sleeps after ~15 min idle (30–60s cold start); restarts wipe in-memory rooms |
| Railway / Fly.io | Fewer cold starts | Free allowance is limited or needs a card |
| Paid always-on instance | Instant every time | ~$5–7/month; the owner chose free |

## Decision

Deploy one Node service on Render's free plan. It serves the built client and the Socket.IO endpoint (`render.yaml`). A GitHub Actions cron (`keepalive.yml`) pings `/health` every 10 minutes when the repo variable `LIVE_URL` is set.

## Consequences

- Occasional cold starts and restarts that end live games are accepted for a demo, and the README says so.
- Persistent storage arrives in R3 and will need its own ADR (database and auth).
- `stories` will list the R1 stories that depend on hosting once they exist.
