## Context

Design doc §9 left the visual design of the game to R1 design, to be shown to the owner as mockups. Claude built two directions, each with three screens (lobby, drawing turn, results): [Screwdle UI Mockups](https://claude.ai/artifact/1D4wJxDvyazowQv4FxeHrB).

## Options considered

| Option | Pros | Cons |
|---|---|---|
| A · Sketchbook: paper-cream, ink outlines, hand lettering, one orange accent | Calm; matches the project showcase | Feels like a document more than a party game; the white canvas blends into the page |
| B · Game night: dark navy, rounded cards, Fredoka, bright yellow accent (chosen) | Party-game energy; the white canvas stands out; player colors pop; podium results | Dark UI needs care with contrast; a second look to keep consistent with the showcase |

## Decision

The owner chose **B · Game night**.

**Tokens** (CSS custom properties in `client/src/theme.css`):

| Token | Value | Use |
|---|---|---|
| `--bg` | `#171a33` | Page |
| `--surface` | `#232748` | Panels (scores, chat, toolbar, top bar) |
| `--raised` | `#2d3260` | Player cards, podium steps |
| `--control` | `#3a3f73` | Buttons, the current player's row |
| `--text` | `#f4f2ff` | Body text |
| `--muted` | `#b9b6d9` | Labels, hints (passes 4.5:1 on `--surface`) |
| `--accent` | `#ffd166` | Primary buttons, timer, the selected tool, the host badge, first place; text on it is `--bg` |
| `--success` | `#3ddc84` | "guessed the word" lines, rows of players who guessed (`#1f4d3a` background) |
| `--danger-bg` / `--danger-text` | `#5a2440` / `#ffd6e3` | Clear canvas |

**Type:** Fredoka (500, 700) for headings, the word, the timer and scores, and Nunito (400, 600, 800) for everything else. Both are bundled with the client through `@fontsource` packages, not Google Fonts, because the game must work on a local network without internet (ADR-002).

**Shapes:** 22 px panel radius, 12–16 px for controls. No borders on panels; contrast comes from the three surface levels.

**Player colors** (8, one per seat, picked in join order and changeable on join): `#4f9dff`, `#3ddc84`, `#ff5c8a`, `#ffd166`, `#b388ff`, `#ff9f43`, `#4dd0e1`, `#ff6b6b`.

**Drawing palette (ADR-003),** 16 colors in two rows of 8: `#000000` `#7f7f7f` `#c3c3c3` `#ffffff` `#e53935` `#fb8c00` `#fdd835` `#43a047` / `#a5d6a7` `#00acc1` `#1e88e5` `#3949ab` `#8e24aa` `#d81b60` `#f8bbd0` `#6d4c41`. The canvas itself is always white.

**Screens:**
- **Home:** nickname, color, and "Create room". An invite link opens it with "Join" instead.
- **Lobby:** as in the mockup.
- **Turn** has three columns: scores, canvas, chat.
  - The top bar shows the round, the word (the drawer sees it, guessers see the mask and letter count) and the timer.
  - The drawer also gets the toolbar: palette, 4 sizes, Pen, Eraser, Fill, Undo and Clear.
  - The word choice shows as a centered overlay on the canvas: three buttons and a 15 s countdown.
  - The reveal shows "The word was **house**" over the canvas for 5 s, with each player's points for the turn.
- **Results:** a podium for the top 3, then a list for the rest, and "Back to lobby" (host only).

**Small screens:** below 900 px wide, the columns stack in this order: top bar, canvas, toolbar, chat, then scores as a horizontal strip. Touch targets are at least 44 px.

**Accessibility:**
- The timer has an `aria-label` ("54 seconds left").
- Color swatches are buttons labelled with the color name.
- Chat is an `aria-live="polite"` log.
- Text meets 4.5:1.

**Test hooks** (`data-testid`, used by the Playwright tests): `create-room`, `join-room`, `nickname`, `invite-link`, `copy-link`, `player-list`, `start-game`, `word-choice-<n>`, `word-mask`, `timer`, `canvas`, `tool-<name>`, `color-<hex>`, `size-<n>`, `chat-input`, `chat-log`, `scoreboard`, `podium`, `back-to-lobby`.

## Consequences

- The showcase keeps its own look. The game has its own, which is normal for a product and its project page.
- Bundling fonts adds about 100 KB to the client, which is fine on a local network.
- The mockups are a reference rather than a pixel contract. Small layout changes during build don't need a new ADR, but a different look or palette does.
