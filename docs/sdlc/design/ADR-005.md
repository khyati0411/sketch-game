## Context

US-015 says faster correct guesses earn more, the drawer earns points for each player who guessed, and players who don't guess earn nothing. R1 turns last 80 s (design doc §5). The owner chose a linear time-based formula.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| Linear in time left (chosen) | Easy to explain ("faster is more"); easy to test with exact numbers | Two near-simultaneous guesses score almost the same |
| By guessing order (300, 250, 200 …) | Rewards beating friends | Ignores how fast; the last guesser at 5 s and at 75 s score the same |
| Time plus a first-guess bonus | Most exciting | Two rules to explain and test |

## Decision

All values are integers, computed on the server when it receives the guess.

- **Guesser:** `round(100 + 400 × secondsLeft / 80)`, where `secondsLeft` is clamped to 0–80. An instant guess scores 500, a guess with 40 s left scores 300, and a guess at the buzzer scores 100.
- **Drawer:** 50 points per correct guesser, capped at 300 per turn.
- **No guess:** 0 points.
- **Drawer left:** if the drawer leaves mid-turn, nobody scores for that turn, including guesses already made (design doc §5). Points already added are rolled back.
- **Final ranking:** order by total score. Players with the same score share a rank, and every player tied for first is a winner ("Winners: Asha and Ben").

The constants (`BASE = 100`, `SPEED = 400`, `TURN_SECONDS = 80`, `DRAWER_PER_GUESS = 50`, `DRAWER_CAP = 300`) live in `shared`, so the client can show them in a "How scoring works" note.

## Consequences

- US-015 AC1 (a guess at 10 s beats one at 60 s): 10 s in leaves 70 s, which scores 450; 60 s in leaves 20 s, which scores 200.
- With 7 guessers the drawer reaches the cap (350 → 300). A drawer whose word nobody guesses scores 0, which encourages drawing clearly.
- Test cases repeat these exact numbers, and changing the formula later means a new ADR.
