# Sprint 1 (Rooms, Lobby, Live Drawing) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver SPRINT-01 (US-001 to US-005). Friends create a room, join by link, see a live lobby, the host starts, and everyone watches the drawer draw live.

**Architecture:** The pure room logic lives in `server/src/game/` (no I/O), and thin Socket.IO handlers sit on top (ADR-004). The protocol types and constants live in `shared`. The React client has four screens (home/join, lobby, game) and a canvas that replays the server's action log (ADR-003). It uses the Game night tokens (ADR-007).

**Tech Stack:** TypeScript, Socket.IO 4, Express, React 18 + Vite, Vitest, Playwright, plus `@fontsource/fredoka` and `@fontsource/nunito`.

**Spec:** `docs/superpowers/specs/2026-10-28-sketch-game-design.md`, with `docs/sdlc/design/ADR-003.md`, `ADR-004.md`, `ADR-007.md`, `architecture.md`, `docs/sdlc/test-plan.md` and `docs/sdlc/test-cases/TC-001..TC-012`.

## Global Constraints

- Node ≥ 24, ESM, npm workspaces; the server listens on `0.0.0.0:3000` (ADR-002).
- Players per room: 2–8. Nicknames are 1–20 characters after trimming, unique in the room ignoring case (US-002, ADR-004).
- Room code: 6 letters from `ABCDEFGHJKMNPQRSTUVWXYZ` (no I, L, O). The invite path is `/r/<code>` (ADR-004).
- Logical canvas 800 × 600 with integer points; brush sizes `[4, 10, 20, 40]`; the 16-color palette from ADR-007; white background; a turn's log is capped at 50,000 points (ADR-003).
- Points are batched about every 30 ms (at most 33 ms) (ADR-003).
- UI tokens, fonts (bundled, not Google Fonts), 44 px touch targets, and the `data-testid` names listed in ADR-007.
- Every Playwright test title starts with its TC ID; one test per automated TC (test plan).

## Rulings made while planning (recorded in the SDLC notes)

1. **TC-011 parents.** TC-011 also needs fill and undo (US-008, US-009) and turn endings (US-013). Its parents become `[US-005, US-008, US-009, US-013]`, so it is required once all of them are Done (Sprint 3). TC-009, TC-010 and TC-012 drop "the drawer has chosen a word" from their preconditions, because word choice is Sprint 2. *Cost if wrong:* US-005 closes without its "same picture" check until Sprint 3. The unit replay test in Task 4 covers the mechanism meanwhile.
2. **Sprint 1 game flow.** "Start game" goes straight to a drawing phase with the first player in join order (the host) as drawer. There is no word, timer or chat yet; Sprint 2 adds them. *Cost:* throwaway code. Small, because ADR-004's phase type just gains members.
3. **Disconnects in Sprint 1.** A disconnect removes the player at once. The 60 s seat hold is US-018 (Sprint 4). If the host leaves, the earliest-joined player becomes host. If fewer than 2 players remain during drawing, the room returns to the lobby.
4. **Branching.** All of Sprint 1 goes on one branch, `feat/sprint-01`, with one PR, and each story's work is in its own commits. This replaces one branch per story: the five stories build on each other, and five sequential owner merges would stall the sprint. *Cost:* a larger PR to review.

## Review Focus

1. Malformed socket payloads (a non-string name, a missing code, thousands of points, NaN coordinates) must be ignored, never crash the server. Tested in Task 2 and Task 3.
2. Draw events from a non-drawer or outside the drawing phase must change nothing. Tested in Task 2.
3. Points outside 0–800 × 0–600, or non-integers, are clamped and rounded. Points past the 50,000 cap are dropped. Tested in Task 2.
4. An empty room is deleted after 5 minutes and its code then reads as "Room not found". Tested in Task 2 with fake timers.
5. Resizing the window must keep the picture: the canvas re-renders from the log at the new scale. Exercised in Task 5's e2e through TC-012's phone-size context.

### Task 2: Room registry and game logic (pure)

**Files:**
- Create: `server/src/game/rooms.ts`
- Test: `server/test/rooms.test.ts`

**Interfaces:**
- Consumes: Task 1.
- Produces: `class Rooms` with the following members:
  - `constructor(opts: { rand?: () => number; now?: () => number })`
  - `create(socketId: string, name: unknown, color: unknown): Ack<RoomView>`
  - `join(socketId: string, code: unknown, name: unknown, color: unknown): Ack<RoomView>`
  - `leave(socketId: string): string | undefined`: returns the code of the affected room. It schedules deletion after `ROOM_TTL_MS` when the room is empty.
  - `start(socketId: string): Ack<null>`
  - `begin(socketId, b: unknown): StrokeBegin | undefined`, `points(socketId, p: unknown): StrokePoints | undefined`, `end(socketId, id: unknown): string | undefined`: return the sanitized payload to broadcast, or `undefined` to ignore.
  - `roomOf(socketId): string | undefined`, `viewFor(code, socketId): RoomView`, `socketsIn(code): string[]`, `log(code): Action[]`.
  - `normalizeName(n: unknown): string | undefined`: trim, then 1–`NAME_MAX` characters.

- [ ] **Step 1: Write failing tests** in `server/test/rooms.test.ts`. Use `vi.useFakeTimers()` for the TTL test. Assertions:
  - `create` returns a view with a 6-letter code matching `/^[ABCDEFGHJKMNPQRSTUVWXYZ]{6}$/`, phase `lobby`, one player `isHost: true`.
  - `join` with `''` or `'   '` gives `{ ok:false, error:'name-required' }`; `'sam '` when `'Sam'` is present gives `'name-taken'`; a 9th player gives `'room-full'`; `'ZZZZZZ'` gives `'room-not-found'`; a 25-character name gives `'name-required'`.
  - Colors: the first free `PLAYER_COLORS` entry, unless the requested color is in `PLAYER_COLORS` and free.
  - `start` by a non-host gives `'not-allowed'`; with 1 player it gives `'not-allowed'`; with 2 the phase is `drawing` and the host is `isDrawer`.
  - `begin`/`points`/`end` from a guesser, or during `lobby`, return `undefined` and leave `log(code)` empty.
  - From the drawer: points `[900, -5, 10.6, NaN, 20, 30]` → `[800, 0]`, then `[11, …]`. Non-finite pairs are dropped and values are rounded and clamped. A color not in `PALETTE` or a size not in `BRUSH_SIZES` makes `begin` return `undefined`.
  - Cap: after 50,000 points, `points` returns `undefined`.
  - `leave(host)` makes the next-joined player host. During `drawing`, leaving down to 1 player sets the phase to `lobby` and clears the log.
  - After the last player leaves, the room still exists until `vi.advanceTimersByTime(300_000)`, after which `join` gives `'room-not-found'`.
  - Payload junk such as `join(sid, 42, {}, null)` or `points(sid, { points: 'x' })` returns an error or `undefined` without throwing.
- [ ] **Step 2:** Run `npm test -w server -- rooms`. Expected: FAIL (module not found).
- [ ] **Step 3: Implement `Rooms`**:
  - A `Map<string, Room>` plus `Map<socketId, code>`.
  - Room codes come from `rand`, retrying on collision.
  - The open stroke is tracked per room. `end` closes it.
  - The point count is a per-room counter that resets when the phase changes.
- [ ] **Step 4:** Run `npm test -w server`. Expected: all pass.
- [ ] **Step 5:** Commit `feat(server): room registry, lobby rules and drawer-only action log (US-001..005)`.
